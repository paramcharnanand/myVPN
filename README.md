# MyVPN — Self-Hosted WireGuard VPN on Oracle Cloud Free Tier

A personal WireGuard VPN server deployed on an Oracle Cloud "Always Free" VM, giving encrypted tunneling and IP masking from any device on the WireGuard client.

## Architecture

```
                    Encrypted WireGuard Tunnel (UDP 51820)
 ┌───────────────┐  ══════════════════════════════════════▶  ┌────────────────────┐        ┌──────────┐
 │  macOS Client  │                                            │  Oracle Cloud VM    │        │          │
 │  10.8.0.2/24   │ ◀══════════════════════════════════════   │  Oracle Linux 9     │──────▶ │ Internet │
 │ WireGuard App  │                                            │  wg0: 10.8.0.1/24   │        │          │
 └───────────────┘                                            │  (NAT / masquerade) │        └──────────┘
                                                                └────────────────────┘

 Firewall layers traversed by tunnel traffic:
   1. firewalld on the VM  (UDP/51820 open + masquerade enabled)
   2. Oracle Cloud Security List  (ingress rule for UDP/51820)
```

All traffic from the client is routed through the VPS, so the client's public-facing IP becomes the VPS's IP (verified via `curl https://ifconfig.me`).

## Why WireGuard over OpenVPN

WireGuard uses a much smaller, modern codebase built on state-of-the-art cryptography (Curve25519, ChaCha20-Poly1305), giving it a smaller attack surface, simpler configuration, and noticeably better throughput/latency than OpenVPN's TLS-based stack — ideal for a low-resource 1GB free-tier VM.

## Prerequisites

- An Oracle Cloud account with an "Always Free" VM.Standard.E2.1.Micro instance running Oracle Linux 9
- SSH access to the instance with a user that has `sudo` privileges
- The [official WireGuard client app](https://www.wireguard.com/install/) on the device(s) you want to connect (macOS, iOS, Windows, Android, Linux)
- A public IP assigned to the VM (see [Gotchas](#lessons-learned--gotchas) below — this is not automatic)

## Setup Instructions

### 1. Server-side setup

Clone this repo onto the VM and run the automation script:

```bash
git clone <this-repo-url>
cd MyVPN
chmod +x setup.sh
sudo ./setup.sh
```

`setup.sh` will:
- Install `wireguard-tools`
- Enable IP forwarding
- Generate a server keypair (if one doesn't already exist)
- Open UDP/51820 and enable NAT masquerading in `firewalld`
- Print the manual steps you still need to do (below)

### 2. Manual steps (not scriptable)

**Oracle Cloud console — networking:**
1. Confirm your VCN's internet gateway is provisioned (see Gotchas — the auto-created VCN may not have one by default).
2. Instance → **Networking** → **Attached VNICs** → select the VNIC → **IP Management** → edit the primary private IP → assign an **ephemeral public IP** (also not automatic).
3. **Security Lists** (or Network Security Groups) for your VCN → add an **ingress rule**: UDP, source `0.0.0.0/0`, destination port `51820`.

**Server config — `/etc/wireguard/wg0.conf`:**

Create this file using the server private key generated by `setup.sh` and the values below as a template (replace all placeholders):

```ini
[Interface]
Address = 10.8.0.1/24
ListenPort = 51820
PrivateKey = SERVER_PRIVATE_KEY_HERE

[Peer]
# macOS client
PublicKey = CLIENT_PUBLIC_KEY_HERE
AllowedIPs = 10.8.0.2/32
```

Then enable and start the service:

```bash
sudo systemctl enable --now wg-quick@wg0
```

### 3. Client-side setup (macOS)

1. Install the [WireGuard app](https://apps.apple.com/us/app/wireguard/id1451685025) from the Mac App Store.
2. Generate a client keypair:
   ```bash
   wg genkey | tee client_private.key | wg pubkey > client_public.key
   ```
3. Create a tunnel in the app with a config like:
   ```ini
   [Interface]
   PrivateKey = CLIENT_PRIVATE_KEY_HERE
   Address = 10.8.0.2/24
   DNS = 1.1.1.1

   [Peer]
   PublicKey = SERVER_PUBLIC_KEY_HERE
   Endpoint = YOUR_SERVER_IP:51820
   AllowedIPs = 0.0.0.0/0
   PersistentKeepalive = 25
   ```
4. Add the client's public key as a `[Peer]` in the server's `wg0.conf` (already shown above).
5. Activate the tunnel in the macOS app.
6. Verify: `curl https://ifconfig.me` should return your **VPS's public IP**, not your home IP.

## Security Notes

- **Never commit private keys or a `wg0.conf` with real values to version control.** This repo's [.gitignore](.gitignore) excludes `*.key` and `*.conf` for this reason.
- Treat both the server and client private keys as secrets — anyone with the server's private key plus network access can decrypt/inject traffic on the tunnel.
- Keep `AllowedIPs` scoped as narrowly as possible per peer (e.g. `10.8.0.2/32`) so peers can't spoof each other's tunnel IPs.
- Restrict SSH access (key-based auth, disable password auth) since the VM is internet-facing.

## Lessons Learned / Gotchas

- **VCN internet connectivity isn't automatic.** The auto-created Virtual Cloud Network didn't have working outbound internet access by default — had to use Oracle Cloud's **"Connect public subnet to internet"** quick action to provision an internet gateway and wire up the route table.
- **Public IP assignment isn't automatic either.** Even after fixing the VCN routing, the instance had no public IP until I manually assigned an ephemeral public IP via **Instance → Networking → Attached VNICs → [VNIC] → IP Management → Edit** on the primary private IP.
- **`dnf install` can hang on a 1GB RAM instance.** On the free-tier micro shape, a `dnf install` run hit an OOM-related hang. A reboot cleared it. Subsequent installs were much faster using `--disablerepo="*" --enablerepo="ol9_baseos_latest,ol9_appstream"` to skip the large Ksplice repo metadata pull that isn't needed for this use case.
- **Two separate firewall layers must both be opened.** UDP/51820 has to be allowed in *both* `firewalld` on the instance *and* the Oracle Cloud Security List — missing either one silently drops all tunnel traffic with no useful error message on the client side.
